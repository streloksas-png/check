# Исправленная версия MECM Dashboard

В комплект входят `default.aspx`, `hardware.aspx`, `web.config`, каталог
`App_Code` с обработчиком диагностики и каталог `assets` с локальными библиотеками.
Исходные загруженные файлы сохранены без изменений.

## Что изменено

- Названия ОС кодируются через `HttpUtility.JavaScriptStringEncode(value, true)`:
  кавычки, обратные слеши и HTML-значимые символы не могут выйти из строк JavaScript.
- Ошибки SQL больше не показываются посетителю. Сообщения выводятся с HTML-кодированием,
  а детали передаются настроенным серверным `TraceListener`.
- Код диагностики работает без символа компилятора `TRACE`; сбой журналирования
  не раскрывает исключение посетителю.
- Все десять колонок GridView явно используют `HtmlEncode="true"`.
- Разрешён доступ только `sc\akudahtin`; следующее правило запрещает доступ всем остальным.
- Отключены отладка, ASP.NET trace, HTTP-кеширование страниц и сохранение состояния
  DataTables в localStorage. Добавлены заголовки защиты от встраивания и MIME-sniffing.
- Chart.js 4.5.1, jQuery 3.7.1 и DataTables 1.13.11 поставляются локально, с SRI.
  Их npm-архивы проверены по integrity из реестра; версии и SHA-256 файлов записаны
  в `assets/manifest.json`. Файлы лицензий включены. DataTables обновлён в рамках
  ветки 1.13; русская локализация встроена в страницу и не требует CDN.
- При обновлении графиков запросы больше не выполняются дважды за один POST.

## Установка на IIS

1. Сохраните резервную копию текущего сайта и его конфигурации.
2. Скопируйте обе страницы, `web.config`, `App_Code` и `assets` в корень приложения.
   Если в существующем `web.config` есть дополнительные настройки, перенесите
   исправления в него с сохранением этих настроек.
3. Нужны ASP.NET / .NET Framework 4.8 и IIS с установленной Windows Authentication.
   Для приложения включите Windows Authentication и отключите Anonymous Authentication.
   Эти параметры IIS намеренно не задаются в web.config: соответствующие секции
   часто заблокированы на уровне сервера.
4. Сохранена исходная модель `impersonate="true"` и Windows-аутентификация SQL.
   Проверьте, что SQL получает ожидаемую личность и что `sc\akudahtin` имеет только
   необходимые права чтения представлений MECM. Не выдавайте `sysadmin` или `db_owner`
   ради работы дашборда. Изменение реальных SQL-привилегий требует администратора БД.
5. Используйте HTTPS. Настройте серверный диагностический слушатель с закрытым доступом
   к журналам: по умолчанию `Trace` не гарантирует сохранение сообщений в файл.
   Например, можно подключить `EventLogTraceListener` к заранее созданному администратором
   источнику Windows Event Log. Не публикуйте журналы как статические файлы сайта.
6. Проверьте вход под `sc\akudahtin`, отказ для другой учётной записи и анонимного
   посетителя, а также загрузку данных из SQL. Права записи в файлы приложения
   не нужны пользователю, просматривающему дашборд.

## Проверки в этой среде

Серверные блоки C# и обработчик диагностики компилировались и выполнялись в Mono.
Проверялись девять вариантов строк JavaScript, включая закрытие script-тега,
кавычки, управляющие символы и Unicode, HTML-кодирование GridView, реальные обработчики
сбоев подключения SQL и передача подробностей диагностическому слушателю.

В Chromium проверялись клиентские скрипты из исправленных страниц с тестовыми данными:
оба графика, таблица из 36 строк, поиск и пагинация. Опасные строки оставались данными;
внешних сетевых запросов и исполнения внедрённого скрипта не было. Проверены XML,
порядок правил доступа и контрольные суммы библиотек.

Windows Authentication, полный жизненный цикл ASP.NET в IIS, реальные права SQL,
запросы к вашей БД MECM и постоянное серверное журналирование здесь не проверялись.
